started before that recovery was discovered, so this report includes it as a ninth

## Findings and maintained guidance changes

1. **OpenCode process isolation and storage isolation are different.** A private
   `--standalone` server does not itself select a separate persistent database.
   Official [OpenCode V2 provider storage documentation](https://dev.opencode.ai/v2/docs/cli/providers/#storage)
   describes data-location controls and the authentication stored there. Harness,
   dogfood and clean-room guidance now record this distinction and require access
   verification without copying credentials. The observed restart/error cause
   remains unproven; fresh storage succeeding does not establish causation.
2. **Client exit is not authoritative completion evidence.** Retain native
   session/child outcomes, check active descendants before retrying, and collect
   native exports after idle. Run 02's failed client and successful author are
   both part of the result.
3. **Smoothness needs shape and shading evidence.** Geometry guidance now
   distinguishes profile continuity, tessellation and normals, and requires
   material-faithful views to distinguish CPU face boundaries from actual ridges.
   Intentional creases and facets remain valid when requested. Flat color does
   not require faceted geometry.
4. **Style follows the user's prompt.** The author skill states this directly,
   without making PSX, smooth shading, cloth, textures or scene optimization a
   universal requirement. The variety here argues against an unavoidable PSX
   default, but nine attempts do not establish general style neutrality. The
   cloth and illustration misses remain evidence to track.

Only documentation and maintained skill guidance changed. No runtime workaround
or scene-specific rule was added. Existing author workspaces and the published
1.2.3 package were left untouched. These guidance edits are local and have not
been retested in a new live-model campaign; delivery checks do not prove that
they improve model behavior.

Validation: skill checks (six skills, two registered setup copies), lint, and
36 focused skill/workspace tests passed. A fresh OpenCode workspace and a managed
AGY upgrade from the published package were exercised separately; copied resource
identity and package inclusion are recorded in the closeout evidence. Existing
customization conflict behavior is covered by the workspace tests. No runtime
behavior changed, so the release's full runtime/performance qualification was
not repeated or newly claimed here.
