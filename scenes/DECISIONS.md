**C-03, in detail: a narrow exception for React DOM's listener.**

- **What is exempt.** Section 5.2(1) governs the listeners the kit and the scenes add. React DOM's listener is page infrastructure that React owns. The website already loads React DOM for its own components, so every page that hosts a scene carries this listener anyway. It is exempt from 5.2(1) and from the teardown requirements of 5.3 and B-05, subject to three conditions:
  1. After full teardown from a cold mount, the only document or window listener left is that one non-passive `selectionchange` listener, identified by its type and by React's marker on the document. Nothing else remains.
  2. Later mount and unmount cycles never add a second one: the count stays at one through every B-05 cycle.
  3. REPORT.md lists it as a known limitation of the pinned React DOM, citing the source locations in `evidence/m1/stop-rule-03.md`. The website handoff notes it too.
- **No change of mounting architecture.**

**Standing rule for pinned third-party infrastructure.** When a pinned dependency (React DOM, R3F or three) forces a deviation from the contract, the builder may apply the same pattern and continue, provided that:
- there is no supported fix;
- the behaviour the page can observe (the signatures, callbacks, error codes and events of section 5) is unchanged.

The pattern is to identify the deviation exactly, bound it, assert that it does not grow, and document it. List every such exception in the final message. Any change the page can observe still stops work.
